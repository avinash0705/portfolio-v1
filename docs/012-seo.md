# SEO

**Version:** 1.0
**Status:** Active

---

## 1. Purpose

`004-product-goals.md`'s Non-Goals already reject maximizing traffic, ranking for non-technical search terms, and treating an audience as an end in itself; its Out of Scope section is explicit that search engine traffic is, at most, "a secondary benefit of good writing," never a primary objective. This document exists within those boundaries: it defines how the portfolio remains legitimately discoverable through search, without letting discoverability distort any content or product decision already made elsewhere in this documentation.

**A clarification worth stating explicitly:** `003-information-architecture.md`, Section 6 excludes an on-site search feature — a box a visitor types into. This document is unrelated to that decision. It governs how external search engines discover and represent the site's content; it does not reopen the on-site search exclusion.

---

## 2. SEO Philosophy

> **Search engines are treated as secondary readers of content written for humans, never as the primary audience.**

Content is written first to serve the three personas in `002-user-personas.md` and to satisfy the standards already set in `015-case-studies.md`, `016-agentprep.md`, and `017-journal.md`. Metadata and structural signals are added afterward, to help a search engine correctly represent content that already exists — never the reverse. Nothing on this site is written, retitled, padded, or restructured to chase a search term.

Specifically excluded, regardless of potential ranking benefit:

- Keyword-stuffed prose, titles, or metadata.
- Content padded in length to appear more substantial to a ranking algorithm — directly contradicted by `017-journal.md`'s "short is preferred over padded" standard.
- Clickbait titles that diverge from a page's real content — already excluded by `017-journal.md`, Section 6's title standard; this document does not create an SEO-motivated exception to it.
- Duplicate or near-duplicate pages created only to capture additional search terms.
- Reciprocal linking, link schemes, or any internal link added for a search engine's benefit rather than a reader's.

---

## 3. URL Strategy

Builds directly on `027-application-behaviour.md`'s Stable URLs policy — this document adds the structural principle that policy depends on:

- URLs are human-readable and reflect the actual content they point to, not an opaque identifier.
- URL structure mirrors the sitemap hierarchy already defined in `003-information-architecture.md` — an individual Case Study or Journal Article's URL reflects that it belongs to that section.
- **A URL slug, once published, does not change even if a page's title is later refined.** Title copy may improve over time; the URL a visitor bookmarked or shared does not move underneath them. Where a URL genuinely must change, `027-application-behaviour.md`'s redirect requirement applies without exception.

---

## 4. Metadata Strategy

- Every page has a unique, accurate title and description reflecting what that specific page actually contains — never a generic templated description duplicated across pages.
- Titles and descriptions are written for a human scanning search results deciding whether to click, not stuffed with search terms for an algorithm.
- A Case Study's or Journal Article's metadata states the real subject plainly, consistent with the honest-title standard already established for the content itself (`015-case-studies.md`, `017-journal.md`) — metadata is never a more sensational version of a page's real title.

---

## 5. Structured Data

Structured data is added only where it accurately represents content genuinely present on the page — for example, marking up a Journal Article's author and publish context, or a Case Study's real title and description. It is never used to claim something the page doesn't actually show.

**Explicitly forbidden:** fabricated review or rating markup, or any structured data implying third-party endorsement — this would directly contradict `003-information-architecture.md`'s site-wide exclusion of testimonials and `000-philosophy.md`'s "Evidence Over Claims." Structured data is a technical description of real content, never a claim manufactured for search visibility.

---

## 6. Internal Linking

Internal linking already exists throughout this documentation for reader-facing reasons — Resume and Experience link to Case Studies (`018-resume.md`, `026-experience.md`), Homepage features Case Studies and Journal entries (`014-homepage.md`), and Journal entries may reference related entries where a genuine connection exists (`017-journal.md`). This document does not add new links for search engines' benefit; it recognizes that the linking structure already required for real persona journeys (`003-information-architecture.md`, Section 5) is also what makes the site legible to a search engine, as a byproduct — not the reason it exists.

No link is added to a page solely to improve that page's search visibility if it would not otherwise help a human reader navigate to genuinely related content.

---

## 7. Content Discoverability

- Every publicly navigable page defined in `003-information-architecture.md` — including link-discovered pages (individual Case Studies, Journal Articles, AgentPrep) — is discoverable to search engines; nothing is hidden to manufacture a sense of exclusivity.
- No content is created solely to rank for additional search terms — this would directly violate `017-journal.md`, Section 3's publishing criteria and `015-case-studies.md`, Section 2's qualification criteria, both of which already require genuine substance as the bar for publishing, independent of any SEO consideration.

---

## 8. Indexing Policy

- All published, qualifying content (per `015-case-studies.md`, `016-agentprep.md`, `017-journal.md`'s own publishing standards) is indexable.
- Draft, unpublished, or retired content is excluded from indexing rather than left crawlable in a stale or incomplete state.
- Where a page is retired or moved, `027-application-behaviour.md`'s redirect policy applies, and search engines are signaled accordingly — a broken or orphaned indexed URL is treated as a defect.
- Where a preview (a Case Study Preview or Journal Preview, `008-component-library.md`, Sections 5–6) and its full page both exist, indexing signals point to the full page as the authoritative version, avoiding duplicate-content ambiguity.

---

## 9. Social Sharing Metadata

The Fellow Engineer persona (`002-user-personas.md`) frequently arrives via a shared link (LinkedIn, direct share) rather than through site navigation — `027-application-behaviour.md`'s Stable URLs policy exists partly to serve this. Every shareable page (Homepage, a Case Study, a Journal Article, AgentPrep) carries accurate social preview metadata:

- The shared title and description match the page's real title and content — never an alternate, more sensational version crafted just for sharing.
- Any preview image is a real, non-decorative representation of the content (a real screenshot, or a plain typographic card stating the actual title) — consistent with `006-design-system.md`'s rejection of stock or decorative imagery. No preview image implies content that isn't actually on the page.

---

## 10. Monitoring Philosophy

Consistent with `004-product-goals.md`'s single-author constraint, SEO monitoring is periodic and lightweight, not continuous rank tracking:

- Indexing status and any crawl errors are checked periodically, not obsessively — sufficient to catch a real problem (a broken URL, a missing page) without demanding ongoing operational attention.
- Success is measured against the same standard as everywhere else in this documentation: whether a search-driven visitor is a genuine match for one of the three personas and can complete a real journey (`003-information-architecture.md`, Section 5) — not by raw impression or ranking volume, which `004-product-goals.md`'s Non-Goals already reject as a measure of success.

---

## Review Checklist

- [ ] No content, title, or metadata was written or altered to chase a search term rather than to serve a real reader.
- [ ] Every page has a unique, accurate title and description matching its actual content.
- [ ] No structured data claims anything not genuinely present on the page; no fabricated review/rating markup exists anywhere.
- [ ] Every published URL is stable; any retired or moved page redirects rather than breaks (`027-application-behaviour.md`).
- [ ] Internal links exist because they serve a real persona journey, not because they were added for search visibility alone.
- [ ] All qualifying published content is indexable; drafts and retired content are not.
- [ ] Social sharing metadata (title, description, preview image) accurately matches the real page for every shareable URL.
- [ ] SEO monitoring remains periodic and lightweight, and success is judged by genuine persona-journey completion, not traffic volume.

---

## What This Document Is Not

This document does not specify meta-tag markup, sitemap.xml generation, robots.txt syntax, or any hosting-platform-specific SEO tooling — those are implementation decisions for `020-tech-stack.md`. It defines the discoverability standard any such implementation must satisfy, and the boundary that standard must never cross.
